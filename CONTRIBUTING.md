# Contributing

Read the locked question and pause state first. This public repository preserves a provisional research record. Documentation fixes, public-tool improvements and methods feedback are welcome now. Further scientific screening needs Cole's instruction.

## Make a first contribution

1. For a question or problem, open [an issue](https://github.com/Open-Source-Research-Initiative/medical-xr-from-capabilities-to-sustainable-use/issues/new/choose) with the page, file, command or publication ID. Use **Join the project** to offer help.
2. For a small documentation fix, use GitHub's edit button on the file. GitHub can create a fork and branch for your proposed change. For local work, fork the project, clone your fork and create a branch; [setup instructions](docs/quickstart.md#explore-locally) explain the tools.
3. Make a bounded change and open a pull request from your branch to this repository's `main`. Link the issue or relevant source/result version.
4. Report checks actually performed, their results and performer, material agent assistance and human review still needed. The PR template prompts for these details.
5. Respond to review. Required CI must pass. Cole records acceptance of the exact revision before merge; proposing a change does not require organization membership or direct write access.


Follow [OSRI-0.1.0](https://github.com/Open-Source-Research-Initiative/osri/blob/8c39a0a36c0e962060659b1d51f666c367f9464a/governance/contribution-standards.md). Keep editable sources and preserve original independent decisions. Repairs require ordered, source-attributed additions. Shared DOIs do not authorize merging. Never redraw the original audit sample.

The [public data release](data/README.md) includes the frozen original records and source materials cleared by Cole on 15 November 2026. Use its catalog and manifest to reference those versions. New source uploads need their own recorded permissions and notices. Keep credentials, unrelated private conversations and controlled Git bundles outside public contributions. Access to the released record needs no invitation.

Use scripts/verify_public_tree.py for the public record. Earlier local-package checks describe the controlled draft. Repository publication does not establish scientific validation, final inclusion or external peer review.

Cole authorizes acceptance and publication within the task's scope. Original code is MIT; original prose and project decision metadata are CC BY 4.0 under the recorded instructions. Respect [LICENSE.md](LICENSE.md), notices and source-specific terms.

To offer help, follow [Join the project](docs/join-the-project.md). Anyone can read, download and fork the public repository; Cole coordinates scientific assignments and write permissions.

For a human source-check proposal, follow the [source-first procedure](docs/human-verification.md) and [submission instructions](data/proposed-human-checks/README.md). Cole coordinates the bounded task. Save your own assessment before comparison, disclose prior AI exposure and never label agent work as human review. Submit a separate proposed result; keep the blank template, original ledgers and verification totals unchanged. Screening stays paused.

For code or data-format changes, run the [public checks](docs/publication-checks.md). For a browser-only documentation edit, check the affected wording and links and state that local tests were not run; required CI still runs on the PR. Automated checks complement source and meaning review. Human acceptance must name the exact reviewed revision; no agent may record its own approval as Cole's review.
